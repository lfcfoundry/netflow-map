Netflow Map: first version vs now

Lays out the same maps with the very first Netflow Map (2026.10.14.2136, then called Net Flow Map) and with the version in this page (__VERSION__, with every update since), taking turns, and tells you in plain words what changed. Nothing leaves this page.

Each picture is the finished layout from the run above it, drifting slowly so the drawing speed shows as FPS (frames per second, higher is better). Big maps show every 2nd, 3rd... link so the picture stays drawable (the count is in the caption). Drawing is paused while a layout is being timed, so it does not disturb the layout numbers.

The verdict

    Layout time, same map, one after the other

    "Typical" is the middle of the runs, "best" the fastest. Lower is better in every time column. "Times faster" is typical first version divided by typical now (higher is better). A run that passed the time limit was stopped and counts as the limit, so those rows say "at least".

    Drawing speed of the finished picture

    FPS while the finished layout is drawn and slowly panned in this browser (higher is better). Taken once per map, in the first turn, one picture at a time.

    Idle memory of the layout links (what the compressor does)

    The first version keeps every link of a finished layout as a plain object. Now, once a big map has been left alone for 4 seconds, the links are packed by memory-compression 2.0.2 and the objects are let go. "As objects" is an estimate (a rule of thumb, usually within a third); "packed" is the real size of the packed bytes. Lower is better in every size and time column. "Exact" says every link came back with the same values. These maps are made up and very regular, so they pack far better than real data usually does; real data will be less dramatic.
