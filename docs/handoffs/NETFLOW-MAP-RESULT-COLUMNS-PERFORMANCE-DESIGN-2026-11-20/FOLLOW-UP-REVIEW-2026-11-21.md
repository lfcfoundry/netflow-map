# Follow-up review: validate the merged sliced decoder

**Current base:** Netflow Map main `e0a02b3` (PRs #224–#227). The original design’s `b1281df` baseline and the prior follow-up base `fc844706` are historical. Read this note with the original test matrix and benchmark protocol before doing more work.

## What landed

PR [#224](https://github.com/lfcfoundry/netflow-map/pull/224) took the RC-02 path: large packed results reconstruct in slices, a newer build cancels stale reconstruction, and generated literal row factories keep common shapes fast without `eval`; unlisted shapes retain the generic unpacker. The PR added pack-shape tests and reports 254 Chromium, 230 Firefox, and 241 WebKitGTK checks passing. At 50,000 Network nodes, the PR reports first-picture time from 2,590 to 2,469 ms in Chromium and 2,668 to 2,391 ms in Firefox, with the longest task over 50 ms reduced 11% and 19%. The recorded picture comparison was within the old-versus-old noise floor for Network, Sankey, and Flow.

This is meaningful RC-02 evidence. It does not establish the RC-01 typed-column prototype, and the PR description does not record a measured RC-00 breakdown or why RC-01 was skipped. Do not rerun the optimization just to repeat the same claim; close the evidence gaps below against current main.

## What landed since the prior review

- PR [#225](https://github.com/lfcfoundry/netflow-map/pull/225) starts a full layout in the background about 40 ms after data or a layout setting changes while a non-Map tab is open. The first Map view then avoids the layout wait; opening Map during a build joins that work, while a newer data change supersedes it. This has no size cap and spends work even when Map is never opened. At 300 ms after import, the PR reports Sankey first-picture medians of 15/40 ms for 1,500/5,000 items in Chromium (previously about 115–140/380 ms) and 7/16 ms in Firefox (previously 86/247 ms), with picture similarity at 99.9%. Card-drawn paths were skipped in the cloud run.
- PR [#226](https://github.com/lfcfoundry/netflow-map/pull/226) prepares the layout-key columns/hash in the worker while the page receives the file. Its 50k-item/100k-link CSV run reports the page's build request around 480 ms instead of 560 ms, with picture-ready times of 1,150–1,208 ms instead of 1,208–1,239 ms (about a 4% stacked improvement); it also updates two browser-suite blocks to wait for a background build sharing their client.
- PR [#227](https://github.com/lfcfoundry/netflow-map/pull/227) vendors `netflow-plot` 2.21.0. The separate JS-modules main now has 2.22.0 summary-only line-chart input, but Netflow Map has not vendored that version on this base. Do not claim the summary input is integrated. If a result card already owns the compatible summary bins, propose that as a separate opt-in experiment and measure its conversion, file-size, and picture costs before changing the vendor.

These releases reduce latency on the Map-first path and on file-to-layout dispatch, but they add background CPU work, shared-client overlap, and key/data association cases that the earlier sliced-decode plan did not cover. Measure them as separate stages rather than combining their gains.

## Remaining verification

1. **Pair count and raw evidence.** PR #224 reports eight alternating fresh-page pairs. The original protocol asks for at least ten pairs on the largest cells and twenty on smaller cells. Rerun the 50k Network cell with ten or more pairs and a below-threshold control; include raw, lossless samples, exact browser versions, device/CPU class, viewport, and commands. The PR points to `/mnt/project-files/netflow-map/result-handoff-rc02-2026.11.20/RESULTS-sliced-decode-row-factories.md`; that evidence is outside the repository. Preserve a privacy-safe reproducible summary and raw synthetic data with this handoff or its linked result artifact.
2. **Cancellation and publication.** Test a second build arriving before the first slice, between slices, and after the last slice but before publish. Assert only the newest complete layout is published; canceled work releases references and cannot call completion twice. Include page close and repeated supersession.
3. **Card and renderer coverage.** The PR says card-drawn paths were skipped in its run and refers to a separate laptop run. Record that run’s raw artifact and exact device/browser, then cover each available Canvas 2D, WebGL 2 and WebGPU path. An unavailable backend is a skip, not a pass. Confirm input, hit testing, drag/pin, saved layout, and export are unchanged after a sliced build.
4. **Shape-generator maintenance.** Verify `tools/gen-pack-shapes.mjs` reproduces `src/pack-shapes.js`; add or retain a test that detects a missing or reordered row shape. Exercise both generated and generic fallback shapes under the production CSP.
5. **Background-build lifecycle (#225).** Cross data arrival and layout-setting changes with Map tab already open, another tab open, and navigation to Map before the 40 ms delay, during work, and after completion. Supersede a build before its first slice, between slices, and after work but before publish. Assert one latest complete layout, no duplicate completion, correct GIF-drop notice, and released references. Include small and large graphs and a never-open-Map control; report total import-to-ready cost, background CPU, longest task, and first-Map delay separately. A no-size-cap policy makes the very-large size ramp and cancellation path important; stop before UI instability.
6. **Worker key/data pairing (#226).** For the same CSV bytes, compare worker-prepared versus prior page-prepared layout-key columns/hash and verify the resulting saved-layout key is exactly stable. Repeat with changed topology, options, labels, duplicate labels, invalid/filtered rows, empty input, and two rapidly successive imports. Assert that a late key result can never be applied to newer rows. Measure file read, key preparation, page receive/adopt, build dispatch, and first picture as distinct timestamps; add a control that disables overlapping work to expose any contention.
7. **Card-drawn coverage and shared-worker serialization.** Both #225 and #226 say their cloud run skipped card-drawn paths and defer to a laptop run. Attach that run's raw artifact and device/browser identity; then cover each available Canvas 2D, WebGL 2, and WebGPU path. Exercise browser-suite cases that share the client while an open-map build is active, including cleanup after a parked worker. An unavailable backend or missing laptop artifact is an explicit gap, not a pass.

Keep first-picture latency, longest main-thread task, total completion, background CPU, key-preparation time, and picture parity separate. A smaller task that delays a usable picture is not automatically better. Re-test ordinary small results, large results, and a never-open-Map control so the threshold does not regress the common path or quietly charge work to users who never open the map.

## Decision boundary

If the follow-up reproduces the result and closes the listed coverage/evidence gaps, record RC-02 complete. If not, isolate the failing browser/path and propose a narrow fix. Do not begin RC-01 or a second optimization unless a new measurement shows a remaining material bottleneck. This review changed no Netflow Map source or tests; it records the next qualification work.
